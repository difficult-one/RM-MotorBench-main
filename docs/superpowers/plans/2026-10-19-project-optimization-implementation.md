# 测试台优化实施计划

依据：`docs/2026-10-19-project-optimization-proposal.md` 第 8 节。用户于 2026-10-19 要求“实施”，按推荐路线 B 和里程碑一、二执行。原提案中的“待评审”描述是起草时状态。

**目标**：基础操作集中在控制台，PID 按需展开；兼容现有 USB 协议，补齐输入校验、自动重连、状态同步和单控制者规则。

**架构**：Vue 3 + TypeScript + Vite；浏览器共享定义不引用 Buffer；Node 负责唯一串口会话、板端事实和命令校验；沿用 ChannelBindings 与有界 SpeedHistory/Canvas。

**约束**：登记与通道上限均为 8；保留旧 PID 记忆；控制指令不在重连时重放；用户识别的通道只恢复显示；不提交或修改 Git 索引；不删除嵌套副本；不连接真实串口、不烧录。

- [x] 基线：运行现有测试，备份原始主机文件和 Git 索引；主副本以附带提案所在仓库为准。
- [x] 服务行为测试：真实 HTTP/WebSocket + 模拟串口，覆盖非法输入、观察者权限、接管全停、控制者断开全停、串口会话快照与异步切换。
- [x] 服务实现：共享型号/量纲/默认值；统一命令校验；请求 ID、发送结果与板端结果分开；操作超时；串口串行；快照；控制租约；目标合并，全停清除目标。
- [x] 前端行为测试：重连不重放输出，快照同步后才开放操作，旧 PID 数据按身份迁移且损坏回退，草稿不被迟到报表覆盖。
- [x] 前端实现：顶栏状态/急停、通道列表、控制及波形、可展开 PID 面板、设备诊断、遥控与四轮配置。离线提供连接引导；已占用但身份未知的通道提供显示识别和显式解绑。
- [x] 固件测试先行：A/C 板实际 DM 解码回调驱动在线状态，超时停止，恢复反馈后需重新使能。
- [x] 固件实现：两个板目录的相同业务修改同步；保留板级适配。不扩大本轮到协议升级。
- [x] 验证：协议、历史、绑定、服务、前端、固件行为、A/C 构建；桌面/平板/390px 手机浏览器实际检查；统一 check 命令、启动说明、交付与实物验收边界。
