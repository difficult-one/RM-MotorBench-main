# Stepper Control Implementation Plan

**Goal:** Add pulse and configurable Modbus RTU stepper operation to the existing motor workbench.

**Architecture:** Keep CAN channels unchanged. A dedicated pulse protocol uses board session/sequence confirmation and an injected hardware pulse driver. A host RS-485 controller shares existing ownership and stop lifecycle. Both appear in a dedicated workspace.

**Tech Stack:** Vue 3, TypeScript, Node serialport, C11, STM32F4.

## Global Constraints

- One pulse axis and one RS-485 device; no invented vendor register map.
- No automatic enable after reconnect. Disable on control loss and cancellation.
- Pulse frequency <=10000 Hz; electronic pulses/rev 200..1000000.
- Readback and generated pulse estimates must be distinguished.

## Tasks

- [x] Protocol and validation: create `stepper_protocol.js`, `modbus_rtu.js`; test hand-checked RTU fixtures, CRC corruption, word order, nonfinite/range rejection and pulse report layouts with `node --test ../tests/stepper_protocol_test.mjs`.
- [x] Firmware: add portable `stepper_pulse.c/.h`, board TIM7 GPIO adapter and private protocol extension for both boards. Verify actual rising-edge count, bounded moves, reverse setup, disable and overflow with a native C executable; compile both firmware images.
- [x] RS-485 controller: serialize exchanges and validate full replies, implement profile-driven motion, readback, cancel and fail closed on communication errors. Test real controller over an injected serial device with byte-level replies, delayed writes and emergency cancellation.
- [x] Bridge and demo: route pulse commands through board session sequence tracking; independent RS-485 connection; add snapshot/status; unify all stop triggers and serial port exclusion. Test using actual WebSocket bridge and simulated board/serial device.
- [x] Frontend: add `StepperPanel.vue`, preserve draft vs applied config, pulse and RS-485 selectors, disabled/error/feedback states and wiring guidance. Verify production build with browser on desktop and 390 px mobile.
- [x] Delivery: run existing checks, independent review, document wiring, profile format, verified software checks and hardware limitations in host README and delivery note.

Code steps use test-first iterations. The initial repository has no commits and already contains staged user work; leave that index untouched.
