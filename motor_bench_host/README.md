# 电机测试台上位机

Vue 3 + TypeScript 工作台、Node WebSocket/串口桥接。配套 A/C 板现有 USB CDC 固件；首次使用需准备对应板型固件。

## 启动

需要 Node.js >=22.18、npm。离线运行前先在有依赖包的环境完成安装和构建。

```powershell
npm ci
npm run build
npm start
```

访问 http://127.0.0.1:3000。服务只提供 dist 内资源；修改界面后重新 build，刷新浏览器。默认只监听本机。HTTP 端口可用 `node server.js --port 8080` 指定，串口由界面连接，服务启动不自动打开真实串口。

前端开发：另一个终端运行 `npm run dev`。Vite 的 `/socket` 代理转发到本机 3000 服务；生产构建不需要 Vite 常驻。

## 无硬件演示

不接线也可以使用：点击未连接页面的「进入无硬件演示」。服务内部模拟 4 颗 M3508 和 1 颗 DM，初始全部停机，通信继续经过相同的协议解析和通道确认。可操作目标、PID、模板、记录和回放；顶栏和导出持续标注「演示 · 模拟数据」。模拟遥控状态用于界面预览，不代表真实接收机或电机动态性能。

演示与真实串口互斥，须在「设备与诊断」退出当前模式，再连接另一种模式。进入/退出会新建串口会话、清除旧绑定事实，运行不会自动恢复。服务启动不会自动进入演示。

## 基础闭环

1. 给板和电机按实际接线供电，通过 USB 数据线连接电脑。
2. 连接引导中刷新串口，核对设备描述并连接。枚举不足时不会假定某个 COM 口就是测试板。
3. 在「设备与诊断」登记型号、总线和电调 ID。清单是板端登记结果，不是自动发现。应用最多 8 颗电机、8 通道；接线冲突说明集中在该页帮助中。
4. 控制台选择通道，选登记电机和控制环，绑定并等待确认与遥测。新固件通过绑定应答和通道查询恢复真实身份；旧固件未知通道可「仅识别显示」恢复图表，运行前先解绑再绑定。
5. 使能从零目标开始。输入框是准备发送的草稿，点击「下发目标」后再核对板端当前目标。「目标设为 0」不是编码器校准；「停止输出」会禁用输出。
6. 顶栏全局急停无需确认框。界面分别显示请求已发送、已知通道禁用反馈及失联未确认。

电机备注按型号/总线/ID 保存在当前浏览器。每次改绑需显式解绑；解绑完成才释放通道。登记信息在板断电后需要重新配置。

## PID 与波形

点击「PID / 专业调试」展开参数。表格分别展示本地编辑、最近板端读回、型号默认值，差异以文字/颜色辅助表达。读回不覆盖草稿，可显式复制读回值。应用成功会停机，须重新使能。DM 当前固件不支持运行期 PID 写入/读回，界面明确限制。

旧 `motor-bench:pid:v1:<型号>:<总线>:<ID>:<环>` 记忆按身份迁移到 v2；损坏或不可用时提示并回退默认值。记忆是本地编辑，不代表板端当前参数。更换浏览器、访问地址或清除网站数据会影响记忆。

DJI 速度是转子 rpm，DM 是 rad/s，角度是 °；DJI 电流是原始量，DM 转矩为协议映射、未校准。当前不显示未经实测校准的功率或效率结论。

图表复用有界 Canvas：最近 60 秒、每通道最多 6000 点，5/10/30/60 秒窗口。蓝色虚线是板端目标，绿色实线是实测。非速度环不绘制目标转速对比。暂停/清空仅影响显示，电机运行不受影响；切换工作区继续采集。时间是主机接收时间，不能当作精确板端采样时间。

「PID 预设与导入导出」支持命名、复制及 JSON 文件预览，最多 20 个本地预设。型号和参数环匹配后才能「填入本地编辑」，这个操作不会写板端；写入仍须点击原「应用到板端」并等待结果。

展开「多通道分析 · 游标与缩放」可选择多个速度环，调节 5/10/30/60 秒窗口与游标。每通道保留最多 6000 点/60 秒；rpm 与 rad/s 分开纵轴，虚线目标、实线实测，同通道使用同色。反馈离线或间隔过大时断开曲线。

## 配置模板与实验记录

「配置模板」保存登记清单、电机备注、通道/控制环和控制来源，最多 20 个本地场景。JSON 导入只预览，表格列出当前与目标身份，包括移动电机后原通道的「解绑后空闲」；明确点击「全停并应用登记与绑定」才会执行。应用先全停并等待遥测，再按差异解绑、登记、刷新清单、绑定并确认控制来源；未列出的其他登记保留。不会恢复使能、运行目标或自动写 PID。中途失败提示已生效的部分，需核对状态，不自动回滚。

「测试记录」开始/结束采集不改变电机运行。服务内存保留最近 5 条，每条最多 60000 样本、1000 事件或 10 分钟；满额、串口会话结束或板端失联自动结束采集。重启服务会丢失记录，请及时导出 JSON；备注与名称可编辑，也可删除已结束记录。

记录保留主机接收时间、电机身份、控制环、各字段单位、在线/使能、目标/实测、固件/会话、控制来源、已读回的 PID 快照以及操作事件。未读回 PID 时不假定其值；未知身份保留空字段。JSON 可离线导入，只在本页回放，不写入服务记录库。CSV 分 metadata/sample/event 行，包含配置上下文，并转义引号和表格公式前缀。

只读回放支持播放/暂停、时间位置、窗口与游标读数；与实时控制独立，不下发运行指令。来源明确标为服务记录或离线文件；服务加载的记录可保存服务端备注，离线文件即使 ID 相同也只改本页数据，须重新导出保存。不同单位独立绘图；非速度环原始样本保留在导出数据中，不伪装成转速目标。导入有格式、版本、数值、身份和体积校验；配置/PID 单文件最多 100000 字符，记录最多 25000000 字符。

## 协议能力与自动测试

新固件1.3通过协议v2协商绑定应答、通道查询、板端时钟和测试能力。在「设备与诊断」可查看能力、板端时间、最近停机原因并刷新绑定。HELLO回显主机挑战，板端硬件RNG生成会话；关联序号和完整身份用于拒绝迟到/跨会话应答。RNG不可用时关闭新增能力。完整帧布局见 `../docs/superpowers/specs/2026-10-19-protocol-tests-design.md`。

控制台展开「自动测试 · 板端执行」，选择阶跃、斜坡或正反转，核对幅度、基线、保持/升幅和零目标尾段。仅当前控制者、网页来源、已确认且反馈新鲜的速度环、全部通道停机且无其他记录时可开始。「开始测试并使能」会实际使能当前通道；运行期间手动目标/PID/换绑受限，仍可取消或全局急停。完成、取消、反馈/心跳/USB失联、控制权丢失或会话变化均停止，不重连续跑。

幅度上限：GM6020/M3508 6000rpm，M2006 7000rpm，DM 40rad/s；基线/尾段各500–10000ms，单阶段200–30000ms，总长不超过120s。阶跃为零→正幅保持→零尾段；斜坡为零→线性升幅→等长保持→零尾段；正反转为零→正幅保持→500ms零段→负幅保持→零尾段。均由板端计时并最终禁用输出，不自动整定PID。

自动记录在结束时保存配置、单位、会话、板端起点、停止原因及带板端时间的样本，在「测试记录」只读回放中查看评价并导出JSON/CSV。阶跃各恒定目标段显示相对幅度超调%、稳定时间及末20%均值误差（目标减实测）；稳定带为幅度2%且至少1rpm/0.01rad/s，持续至少200ms。斜坡仅评价保持段稳态误差。初始基线和反向前零段的末200ms须稳定；样本须身份一致、同会话、在线、时间递增，间隔不超过100ms，首尾覆盖完整。条件不满足会显示原因，不生成有效指标。

图表横轴仍为主机接收时间，动态评价使用板端读取反馈时刻，不等同电调内部CAN采样时刻。模拟数据仅用于功能体验。旧固件的手动控制保持兼容，自动测试会提示升级；旧记录不含板端时间，仍能回放但不能得到本轮动态评价。

## 控制来源和多页面

「控制方式」支持网页、单电机 DT7/DR16、麦克纳姆及四轮全向底盘。底盘需四个同型号 DJI 速度环通道，按 FL/FR/RL/RR 及实际安装配置反向。右摇杆上下/左右控制平移，左摇杆左右控制旋转；右拨杆上档、两摇杆回中后使能。麦轮使用 X 型辊子布局，全向轮使用四轮 45° X 型切向布局。实际方向须低速验收。

A 板 DR16 为 USART1，C 板为 USART3。切换来源、成员解绑/PID 改写、遥控器失联、成员离线或全停均会停止组输出，恢复须重新使能。服务只标记底盘使能请求已发送，是否输出以各通道遥测为准。

首个页面取得控制权，其余页面观察，可主动接管。接管先全停；控制页面断开或约 4 秒收不到控制权心跳会请求全停；观察页面关闭不影响控制者。WebSocket 自动退避重连，先同步快照，运行/使能指令不会重放。板端约 1.5 秒收不到服务心跳会自行全停；本轮 DM 修正固件另有 500ms 电机反馈门限。

浏览器请求 ID 只关联到服务和可匹配的ACK；v2绑定/测试额外关联板端会话与序号，其余旧帧没有完整请求关联。操作超时后结果仍可能已经生效；重新查询或连接并核对后再操作，不自动重发运行指令。不要把“已发送”理解为板端成功。

## 检查与浏览器回归

```powershell
npm run check             # lint、类型、构建、协议/服务/前端、A/C 原生行为
npm run test:integration  # 固件 CRC 原生交叉验证，需 GCC
npm run test:reliability  # 真实 HTTP/WebSocket，仅替换串口硬件
npm run test:frontend     # 重连不重放和 PID 迁移
npm run test:workspace    # 模板、容量、导出/导入、回放及损坏数据
npm run test:v2           # 新协议、序列、手算指标、演示计时及真实桥接服务
```

A/C 原生行为测试需要 PATH 上的 GCC，或设置 `NATIVE_CC`。固件分别在各板目录运行 `make -j4`，只构建不烧录。

浏览器回归仅使用回归模拟串口，不会枚举或打开真实串口。在本目录启动：

```powershell
node --import ../tests/support/simulated_board.mjs server.js --port 3301
```

项目根目录另开终端：

```powershell
npx --yes --package @playwright/cli playwright-cli -s=optimization open http://127.0.0.1:3301
npx --yes --package @playwright/cli playwright-cli -s=optimization run-code --filename tests/browser_workbench_regression.js
npx --yes --package @playwright/cli playwright-cli -s=optimization run-code --filename tests/browser_feedback_regression.js
npx --yes --package @playwright/cli playwright-cli -s=optimization run-code --filename tests/browser_legacy_capabilities_regression.js
```

每轮使用新启动的模拟服务。完整流程包含登记/绑定/目标/回传、PID、图表显示、急停、观察者、刷新恢复和五种视口。截图写入 `output/playwright`。早期 `browser_*` 脚本针对旧原生 DOM，已由此流程替代，不作为当前 UI 验收入口。

第三阶段浏览器回归使用内置演示。先在上位机目录运行 `node server.js --port 3302`，再从项目根目录执行：

```powershell
npx --yes --package @playwright/cli playwright-cli -s=analysis open http://127.0.0.1:3302
npx --yes --package @playwright/cli playwright-cli -s=analysis run-code --filename tests/browser_analysis_regression.js
```

覆盖模板文件与真实换绑、占位选择、PID 文件与本地编辑、记录/CSV/JSON/回放、运行目标保持、多单位曲线、轮序反向及五种视口。该回归只操作内置演示，不打开物理串口。

同一3302演示服务可运行新增的 `tests/browser_automated_tests_regression.js`，覆盖能力协商、取消/再次开始、自动完成停机、记录、JSON回放评价和五种视口。脚本会退出旧演示再创建新的模拟会话，不打开真实串口。

## 文件边界

- `frontend/`：Vue 组件、类型、连接、设备状态和 PID 记忆；`index.html` 为构建入口。
- `shared.js` / `motor_rules.js`：浏览器可用的协议事实、量纲与已知冲突规则。
- `protocol.js`：Node Buffer 线协议编解码。
- `protocol_v2.js` / `test_sequence.js` / `test_metrics.js`：新增帧、板端序列公开规则与受采样条件约束的纯评价。
- `bridge.js` / `command_validation.js`：唯一串口会话、控制权、输入校验、关联与有界事件。
- `channel_bindings.js` / `waveform.js`：复用的绑定恢复和有界历史/绘图。
- `workspace_formats.js` / `recording_format.js`：可移植配置、PID、记录校验及纯读取分析。
- `experiment_store.js` / `demo_port.js`：服务端有界记录与无硬件协议模拟。
- 原 `ui.js`、`style.css` 保留作迁移参考，生产服务不提供它们。

本轮范围、验证结果和实物验收边界见 `../docs/2026-10-19-optimization-delivery.md`。
第三阶段交付见 `../docs/2026-10-19-analysis-workspace-delivery.md`。

## 步进电机控制

点击新工作区“步进控制”，可切换脉冲（A/C 板 PU/DR/EN）和 RS-485（电脑 USB-485）两种方式，各支持一台。脉冲提供速度、方向、相对脉冲运动和使能；RS-485 提供可配置 Modbus RTU 寄存器控制。两者支持无硬件演示并共用全局急停。

脉冲须重新烧录本次 A/C 固件，并按实物驱动器核对电平、EN 极性及每圈脉冲；网页脉冲位置为发出计数，未读取编码器。RS-485 须导入与实物匹配的厂家协议配置，当前没有该电机已核实寄存器表，模板不能直接运行。完整接线、配置结构、测试与限制见 [步进控制交付](../docs/2026-10-19-stepper-delivery.md)。已有 Node 服务需重启并刷新页面。
